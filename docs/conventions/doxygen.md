# 项目 Doxygen 注释规范

来源：用户提供的《K03_Doxygen代码注释规范.md》（2026-10-15 核对版）。原文件保持不变；本文件记录适用于当前学习工程的约定。

- 范围：src 下手写 C++。第三方、构建生成代码、备份和临时文件不修改；测试不纳入本次专项治理范围。
- 类/结构体前用 Doxygen 说明真实职责。
- 头文件每个函数、信号、槽、构造和析构均写完整 `/*! ... */` 或 `/** ... */`，包含 brief。
- 每个具名参数分别用 @param，名称与声明一致；非 void 返回值用 @return 说明含义和失败结果。构造/析构不写 @return，无参不写 @param。
- 已删除的拷贝操作保持匿名参数和声明不变，用 @note 说明不可调用及匿名源参数，不虚构参数名；赋值运算符说明不会产生返回引用。
- 成员、结构体字段和枚举项使用行尾 `///<`，按实际情况说明单位、范围、所有权或生命周期。
- CPP 定义前统一 `/// \brief`；函数体内只用普通 `//` 说明原因、约束和异常路径，不加装饰分隔线。
- 注释紧邻对应声明或定义；不编造默认值、异步语义或线程安全；不记录密钥和账号。
- 纯注释提交不修改参数、签名、初始化、类型、逻辑、资源或代码格式。检查去除注释后的 token 序列一致，再编译验收。
- 文件修改注释记录实际北京时间与 wbliu 标识。
- K03 的三个指定主题函数约定仅在对应函数存在时适用；本工程没有这些函数，本次不改 QSS 组织。

用户提供的候选扫描脚本使用 M1～M5 检查头文件函数块、字段尾注、CPP 定义前注释、体内误用和参数/返回值缺口。它是启发式工具，必须人工检查文字含义；零候选不等于语义已经正确。
