特征、描述与匹配

两幅图里怎样找到同一个位置？

问题与直觉

特征定位与描述是两个问题：检测器选有辨识度的位置，描述子把周边结构编码，匹配器根据距离提出候选对应。角点通常比平坦区域稳定，单一直边则沿边方向定位不确定。真正的 ORB 和 SIFT 还处理方向及尺度等变化，本课先用固定像素块学习描述与相似度，不能把模板匹配称作完整特征匹配系统。

数学与手算

归一化互相关 NCC 对每个块减均值，再计算点积除以两者范数。块 [1,2,3] 与 [11,12,13] 去均值后相同，相关系数为一，因此可抵抗不发生饱和的亮度偏移。平坦块去均值后全零，分母为零，没有辨识度；应该先检查标准差并拒绝，而不是相信某个库实现给出的特殊分值。

失败案例与排错

失败实验：重复棋盘产生很多同等好的峰；旋转九十度或改变尺度会破坏固定块对应。最大得分高不意味着唯一，应比较次佳峰并屏蔽最佳峰邻域，避免把同一峰周围像素当独立竞争者。匹配还应经过几何一致性验证。

排错顺序是先确认输入尺寸、类型、通道语义和取值范围，再检查中间矩阵，最后调整算法参数。把每一步输出与未处理原图并排比较，记录参数及观察结论。显示器自动缩放、JPEG 压缩、归一化和伪彩都会改变观感；判断像素值应读取矩阵，不能从截图颜色反推数值。

真实特征 API 的版本边界

官方 4.x 示例的 features2d 头文件与旧模块布局不能直接认定适用于本工程 OpenCV 5。当前离线构建只保证 core、imgproc、imgcodecs、geometry，所以上述实验不引入额外依赖。扩展 ORB/SIFT 时，本地固定源码已核对：modules/features/include/opencv2/features.hpp 第 352、444、1212 行分别声明 SIFT、ORB、BFMatcher，CMake 模块为 features，头文件为 opencv2/features.hpp。补建 opencv_features 及依赖后再写 detectAndCompute、knnMatch 和几何筛选。不要直接复制旧的 find_package 组件列表或悄悄更换到 4.x。浮点描述子常用 L2，二进制描述子常用 Hamming；两种描述不能随意混用距离。

// 可选扩展：必须先构建 features 模块；本课默认可执行程序不使用它
#include <opencv2/features.hpp>
std::vector<cv::KeyPoint> keypoints;
cv::Mat descriptors;
auto orb = cv::ORB::create();
orb->detectAndCompute(image, cv::noArray(), keypoints, descriptors);
// 无关键点时 descriptors 可能为空，应先检查再匹配。

不要把描述子行数直接当成功匹配数，几何验证仍然必需。

自测：先回答再展开

NCC 为一表示唯一匹配吗？

不表示，重复纹理可能处处相同。

常量块为何拒绝？

零方差导致归一化分母为零，也没有辨识信息。

ORB 描述子应使用什么距离？

常规二进制 ORB 用 Hamming，WTA_K 为三或四时按文档使用 Hamming2。

术语

keypoint 关键点；descriptor 描述子；NCC 归一化互相关；ambiguity 歧义
