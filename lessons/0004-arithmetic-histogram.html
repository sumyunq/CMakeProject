图像算术与直方图

亮度增加以后，细节去了哪里？

问题与直觉

图像增强先要回答数值范围。8 位无符号整数只容纳零到二百五十五，OpenCV 的常规图像加法会饱和到端点。转换到浮点再计算可以保留越界中间值，最终显示之前才决定裁剪或缩放。直接用 C++ 的 uchar 运算再强制转换，可能得到模二百五十六回绕，不能和 cv::add 的结果混为一谈。减法、乘法、加权混合都需要同样审查中间类型。

数学与手算

输入 [0,10,250,255] 加二十后，8 位输出 [20,30,255,255]，浮点输出 [20,30,270,275]。两个高亮像素在饱和后不可区分，后来减二十也无法恢复。直方图 h(k) 是等于灰度 k 的像素数，概率 p(k)=h(k)/N；累计分布是前面各箱之和。四个输入像素总计数必须为四，这比只看曲线形状更可靠。

完整可编译入口在 FoundationLabs.cpp 的 case04，共享 main 负责日志、参数检查、目录创建和异常转非零退出码。该实验自行构造输入，不需要下载图片、摄像头或模型。先查看该函数及其调用的 save、require，再运行；不要只抄一个脱离初始化和错误处理的 API 片段。

case04 使用 add、convertTo、calcHist。保存 input.png 与 added.png，并打印两套中间数值。直方图使用 256 个箱，范围 [0,256)，因此灰度 255 在最后一箱而不会被遗漏。直方图本身是浮点计数矩阵，不能直接把它当作输入图像保存。

预测后运行并核对标准输出的数值与中间 PNG。程序断言失败、目录不可写或图像编码失败均返回非零；尝试把课号写成 99，确认入口拒绝无效范围。输出目录必须可创建且可写，不能把已有普通文件当目录。最小实验验证了受控输入的行为，不等于已经验证所有真实业务图像。

失败案例与排错

失败实验：把直方图上界设为 255，会遗漏最大值。另一个典型问题是逐帧独立均衡化造成视频闪烁；相同物体受当前帧整体灰度分布影响而变化。全局均衡化并不保证保留测量的物理亮度关系，CLAHE 则要额外记录网格和裁剪参数。

排错顺序是先确认输入尺寸、类型、通道语义和取值范围，再检查中间矩阵，最后调整算法参数。把每一步输出与未处理原图并排比较，记录参数及观察结论。显示器自动缩放、JPEG 压缩、归一化和伪彩都会改变观感；判断像素值应读取矩阵，不能从截图颜色反推数值。

独立练习

生成 [0,0,100,200,255]，分别进行加三十、减三十以及浮点往返，手写五个非零直方图箱的预期，比较均衡化前后累计分布。

验收标准

加三十得到 [30,30,130,230,255]；原始直方图 h(0)=2，其余指定箱各一，总和五。8 位往返末点变为 225，证明不可逆。

提交输入生成规则、运行命令、至少一个数值表、全部关键中间结果和失败案例。评分：数值正确四十分，边界与错误处理二十分，解释参数和失败原因二十分，可复现记录二十分。八十分且所有关键数值正确算完成本课；能够口头解释为什么成立，比把测试标绿更重要。

自测：先回答再展开

为什么加减相同常数不还原？

中间饱和丢失了高于 255 的信息。

256 箱的上界为什么是 256？

范围右端不包含，才能覆盖 255。

均衡化为何可能放大噪声？

稀疏灰度区间被拉伸时微小差异也被扩张。
