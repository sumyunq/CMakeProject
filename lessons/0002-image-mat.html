Lesson 02 / 看见内存中的图像

一张图像，几个对象，一份数据？

目标：区分像素、通道、矩阵头和像素存储，能预测复制与 ROI 的修改结果。这些知识决定以后的视频流水线是否正确。

问题：复制后为什么原图也变了？

cv::Mat original = cv::Mat::zeros(3, 4, CV_8UC1);
auto alias = original;
auto independent = original.clone();
alias.at<uchar>(0, 1) = 9;
auto roi = original(cv::Rect(1, 1, 2, 2));
roi.setTo(7);

运行前写下 original、alias、independent、roi 的尺寸和最终值；特别注意 at(row,col) 与 Rect(x,y,width,height) 的顺序不同。

图像的数值表示

二维灰度图可以记作 I(y,x)，彩色图像还要增加通道下标 I(y,x,c)。rows 是高度，cols 是宽度；CV_8UC3 表示每通道 8 位无符号整数、每像素 3 通道，通常用于 BGR，但 Mat 类型本身不保存颜色空间语义。

类型每通道每像素注意
CV_8UC11 字节1 字节可表示灰度，也可表示掩码
CV_8UC31 字节3 字节BGR/RGB/HSV 语义由流程约定
CV_16UC12 字节2 字节可能用于深度/高位深图，不应直接当 8 位显示
CV_32FC14 字节4 字节值域由算法决定，不自动等于 0～1

行步长：地址公式

address(y, x, c) = data
                   + y * step[0]
                   + x * elemSize()
                   + c * elemSize1()

这里讨论二维、通道交错的 Mat。step[0] 的单位是字节，elemSize() 包含一个像素所有通道。仅当连续时，才可以把整块数据当作紧密的一维像素序列。

例如父图宽 8、CV_8UC3，其行步长为 24 字节。截取宽 3、高 2 的中间 ROI 后，每行有效数据只有 9 字节，但下一行起点仍相距 24 字节。如果按 9 字节跨行，会读到 ROI 右侧的父图像素。

Mat 头与数据所有权

Mat 对象包含尺寸、类型、步长、数据指针等信息。对正常由 OpenCV 管理的数据做赋值，会共享像素并维护引用计数；clone() 才创建独立副本。Mat 不会在写入时自动为普通浅拷贝执行分离。

外部内存是另一种边界：用外部指针创建 Mat，不会自动接管该缓冲区生命周期。共享引用计数也不代表并发修改像素是安全的。

预测结果

写好自己的结果后，再展开对照
original 与 alias：
0 9 0 0
0 7 7 0
0 7 7 0

independent：3×4，全零
roi：2×2，全为 7

alias 写入共享存储；roi 指向同一份父图数据的一个子区域；independent 在修改之前复制，所以仍全零。这个 ROI 的行步长仍为 4 字节，每行有效 2 字节，因此不连续。

最小实验

./scripts/Run.ps1 -Configuration Debug -Program mat_demo
./scripts/Run.ps1 -Configuration Debug -Program vision_viewer

控制台显示属性、矩阵和 ROI。Widgets 窗口显示生成的红、绿、蓝色块，元数据来自业务检查结果。留意图像宽高与窗口尺寸不同，窗口布局不会改变源图像矩阵。

为什么要复制成独立 QImage？

QImage 的外部内存构造并不自动接管 Mat 内存。如果 Mat 被释放，界面随后绘制可能访问失效数据。本工程转换接口返回独立像素所有权，并测试“修改和销毁源 Mat 后仍可显示”。灰度直接按正确步长复制，BGR/BGRA 先按约定转换通道顺序。

本课显示接口只接受二维 CV_8UC1/3/4。不支持的类型返回明确错误；16 位深度或浮点数据需要后续明确的归一化/显示映射，不静默截断。

失败案例

  • 把 BGR 当 RGB：红蓝互换。用已知纯色块验证，不凭照片观感猜。
  • 把 cols 当 rows：出现转置式坐标错误。先用非正方形矩阵实验。
  • 把 ROI 当连续：首行正常、后续行错位。检查 step 与 isContinuous。
  • 把浅拷贝当线程快照：后台修改影响界面。必须明确只读共享或独立复制。
  • 直接读取超出图像范围的坐标：不是边界策略，而是错误访问；先校验范围。

自测与纵深问题

Mat 类型相同，是否表示同一种颜色空间？

不能。CV_8UC3 只描述深度与通道数；BGR、RGB 和 HSV 都可能用这个存储类型，需要额外的语义约定。

ROI 的 total()*elemSize() 能否作为跨行 memcpy 的字节数？

对非连续 ROI 不可以直接当作一段紧密区域复制。应按行处理，或使用支持步长的库接口，或 clone 得到连续副本。

引用计数是否解决像素的线程安全？

它解决特定所有权管理问题，不替代对共享像素读写的同步。读写并发仍需要约束生命周期、不可变快照或同步。
